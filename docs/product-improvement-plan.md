# Desktop Organizer 产品改进计划

## 刚才发生了什么？

SnowDesktop 启动后创建了一个**覆盖整个桌面的透明窗口**（WS_EX_TOPMOST），
盖住了 Windows 正常的桌面图标视图。即使进程被杀，这个窗口的残留效果
导致桌面看起来是空的。这不是文件丢失——只是被挡住了。

## 核心问题清单

### 1. 致命问题：桌面覆盖窗口（必须修）

**问题**：程序用一个 WS_EX_TOPMOST 窗口盖住整个桌面，一旦程序崩溃/被杀，
用户桌面就"消失"了。

**修复方案**：
- 去掉 WS_EX_TOPMOST，改用 DWM 缩略图 API 直接在桌面壁纸层渲染
- 或者只在桌面上叠加一个半透明小组件面板，而不是覆盖整个桌面
- 加入"安全退出"机制：进程退出时必须恢复 WorkerW/桌面窗口

### 2. 稳定性：崩溃恢复（必须修）

**问题**：程序没有崩溃恢复机制。如果异常退出，桌面状态不会恢复。

**修复方案**：
- 启动时保存桌面窗口句柄到文件
- 注册 SetUnhandledExceptionFilter，崩溃时先恢复桌面再退出
- 添加 Windows 崩溃转储（MiniDumpWriteDump）

### 3. 用户控制：随时可退出（必须修）

**问题**：程序覆盖桌面后，用户无法操作桌面图标，无法通过常规方式关闭程序。

**修复方案**：
- 系统托盘图标必须始终可见（NOTIFYICONDATA）
- 全局热键退出（如 Ctrl+Alt+Q）必须始终响应
- 设置页面必须可通过托盘菜单打开

### 4. 架构改进：不要替代桌面，要增强桌面

**问题**：当前架构是"替代桌面"，正确做法是"增强桌面"。

**修复方案**：
- 桌面小组件改为独立窗口（WS_EX_TOOLWINDOW），不覆盖桌面图标
- Dock/面板改为侧边栏或底部栏，和桌面图标共存
- 保留用户原有桌面图标，只在旁边添加增强功能

## 技术实现路线

### Phase 1: 安全第一（1-2天）
1. 去掉桌面覆盖窗口，改用独立小组件窗口
2. 添加崩溃恢复（异常处理+桌面恢复）
3. 系统托盘图标 + 全局热键退出
4. 测试：杀进程后桌面必须完全恢复

### Phase 2: 稳定性（3-5天）
1. 内存泄漏检查（D2D/DComp 资源必须正确释放）
2. 长时间运行测试（24小时+无崩溃）
3. 低资源模式（CPU < 5%, 内存 < 200MB）

### Phase 3: 用户体验（1周）
1. 设置页面完善（深色/浅色切换、组件开关）
2. 快捷键自定义
3. 组件拖拽布局
4. 第一次启动引导

## 关键代码改动点

- `app_lifecycle.cpp`: 桌面窗口创建逻辑（去掉 WS_EX_TOPMOST）
- `app.h`: 添加崩溃恢复接口
- `main.cpp`: 添加 SetUnhandledExceptionFilter
- `app_paint.cpp`: 渲染管线改为只渲染组件区域，不覆盖全屏
